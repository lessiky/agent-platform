## 1. 已完成内容

### 1.1 实例语义收敛 (M2.5.1)

- Agent config 新增 `simulate_traffic` 开关 (默认 `false`)；实例启动日志记 `instance ready (simulated_traffic=off|on)`。
- 模拟流量生成由开关显式控制 (runtime 注入 agent 级开关检查)：默认关闭不产生模拟日志，开启后生成；模拟日志显式标注 `simulated request ok/failed`，与真实流量区分。
- "实例启动" 语义 = 上线 (可接受对话/调用)，不再隐式产生常驻流量。

### 1.2 系统提示词版本化 (M2.5.2)

- Agent config 新增 `system_prompt` 字段 (`service/agent_service.go` AgentConfig)，创建/更新 API 携带。
- 版本快照：`agent_versions` 的 config 快照包含 system_prompt，参与版本历史与回滚 (回滚随 config 一并恢复)。

### 1.3 模型调用 (M2.5.3)

- `modelclient` 实现 OpenAI 兼容 `POST /v1/chat/completions`：provider 映射、超时、错误分类 (连接/HTTP/解析)。
- 支持 `tools` 工具定义与 `tool_calls` 返回、`usage` token 统计。
- 以 `tools/mock-model-server` 的 `/v1/chat/completions` 固定应答端点验证调用链 (行为：含 role=tool 消息 → 工具轮确认文本 32 tokens；末条 user 含 `CALL_TOOL:<name>` → tool_calls 16 tokens；其他 → 固定应答 18 tokens)。

### 1.4 对话执行引擎 (M2.5.4 + M2.5.5)

```
用户提示词
   │
   ▼
[system_prompt + 最近 10 条历史消息 + 用户消息] + 工具白名单定义
   │
   ▼
M4 路由: agent 首选模型 → 故障候选故障转移, 配额消费
   │
   ├─ 模型返回 tool_calls (至多一轮工具轮)
   │      └─ executeToolCall (M4.5 审核门禁) → tool 消息回传 → 第二次模型调用 (tokens 累加)
   ▼
应答文本 + 执行元数据 { execution_id(8位hex), model_name, total_tokens(该轮模型调用累加), latency_ms }
   │
   ▼
落库 (user/tool/assistant 消息) + 执行日志 start / model ok / done 配对 (均带 execution_id)
```

- 会话持久化：`agent_chat_sessions` / `agent_chat_messages` 表 (GORM AutoMigrate)；消息携带 `execution_id` 与 `execution_meta` (JSONB: execution_id/model_name/total_tokens/latency_ms/mcp_calls/pending_approvals/error)。
- API：`POST /agents/:id/chat` (不传 session_id 新建会话, 传则续聊)；`GET /agents/:id/sessions` (会话列表, title 取首条消息截断)；`GET /agents/:id/sessions/:sid` (会话 + 消息历史)。
- 多轮上下文：最近 10 条历史消息 (常量 `chatHistoryLimit`) 送入模型。
- 会话隔离：访问他人会话返回 404。

### 1.5 对话内工具调用与审核联动 (M2.5.6)

- 工具白名单：agent 绑定的 MCP 已发现工具 ∩ `tools` 白名单过滤；白名单外工具调用记 `skipped (not in allowed tools)`。
- 模型返回 `tool_calls` → 经 M4.5 `CallTool` 审核门禁执行：
  - 非审核工具：直接执行，结果 (ok) 回传模型继续生成最终应答；
  - `requires_approval=true`：不执行，生成审核请求 (**source=`chat`**)，tool 消息按 pending 回传；应答文本照常返回，`execution_meta.pending_approvals` 标注待审核请求 id；
  - 审核通过后经 `ExecuteTool` 执行并回填 result (不重跑模型轮)。
- 工具轮至多一轮，避免循环；tool 消息 (role=tool) 落库，会话历史可见 user,tool,assistant 结构。
- 执行元数据 `mcp_calls` (工具名/状态/参数/结果或 pending 信息) 随消息 meta 持久化。

## 4. 与计划/PRD 的偏差说明

| 项 | 计划/PRD | 当前实现 | 说明 |
|----|----------|----------|------|
| 工具轮次数 | 工具结果回传模型 (单轮) | 至多一轮工具轮 | 第二轮若再请求工具调用不再展开, 防死循环 (mock 不产生二轮请求) |
| 审核等待 (PRD 2.2.4) | 执行流挂起 (waiting_approval) 后恢复 | 异步 pending: 生成审核请求, 对话立即返回应答 + pending 标注, 审批通过后仅回填工具结果 (不重跑模型轮) | 与 M4.5 一致, 进程级挂起/恢复留 M5 工作流执行器统一实现 |
| 历史上下文 | 最近 N 轮作为多轮上下文 | 最近 10 条消息 (user/assistant) | 常量 `chatHistoryLimit`, 可调 |
| 执行元数据 | execution_id/tokens/latency/model | chat API 返回 + 消息 `execution_meta` (JSONB) 持久化 | tokens 为该轮全部模型调用 (含工具轮) 的 usage 累加 |

## 5. 运行方式

无新增 `.env` 配置 (mock-model-server 沿用 9101 端口与模型模板中存储的 API key)。

示例：

```
# 单轮对话 (自动新建会话)
curl -X POST localhost:8080/api/v1/agents/$AGENT_ID/chat -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"message":"hello"}'

# 续聊指定会话 (多轮)
curl -X POST localhost:8080/api/v1/agents/$AGENT_ID/chat -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"session_id":"$SID","message":"第二轮"}'

# 会话列表 / 会话详情
curl localhost:8080/api/v1/agents/$AGENT_ID/sessions -H "Authorization: Bearer $TOKEN"
curl localhost:8080/api/v1/agents/$AGENT_ID/sessions/$SID -H "Authorization: Bearer $TOKEN"

# 对话内工具调用 (mock 触发方式: CALL_TOOL:<工具名>)
curl -X POST localhost:8080/api/v1/agents/$AGENT_ID/chat -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"message":"CALL_TOOL:ticket.create"}'
```
