# Agent 管理平台 — Phase 1 开发计划

> **版本：** v1.0
> **日期：** 2026-08-17
> **周期：** 10-12 周

---

## 1. Phase 1 目标

构建平台 MVP，实现四大核心模块的基础功能：

| 里程碑 | 交付内容 | 周期 |
|--------|----------|------|
| **M1: 基础框架** | 项目脚手架、RBAC 权限、API Gateway | 2 周 |
| **M2: Agent 管理** | Agent CRUD、实例启停、状态看板、日志查看 | 3 周 |
| **M2.5** | ✅ 系统提示词可配置且入版本历史 ✅ 单轮/多轮对话可用 ✅ 模型调用走路由/配额/故障转移 ✅ 对话内工具调用走审核 ✅ 执行日志有明确起止 |
| **M2.5: Agent 对话与系统提示词** | 系统提示词、对话执行链 (模型调用+对话内工具调用)、对话会话、对话 UI | 1.5 周 |
| **M3: MCP 管理** | MCP 注册、工具发现、连通性检测、凭证存储 | 3 周 |
| **M4: 模型管理** | 模型模板 CRUD、连通测试、配额管理、路由选择 | 2 周 |
| **M4.5: MCP 工具调用人工审核** | 工具级审核配置、审核请求生命周期 (通过/驳回/超时)、审核中心、调用链接入 | 2 周 |
| **M5: 工作流引擎** | DAG 定义、节点执行引擎、手动触发、执行日志、MCP 节点审核等待联动 | 4 周 |

---

## 2. 技术选型

| 层级 | 技术 | 说明 |
|------|------|------|
| **前端** | React 18 + TypeScript + Ant Design + Vite | 组件丰富，生态成熟 |
| **后端** | Go (Gin) | 高并发、适合 I/O 密集型 |
| **数据库** | PostgreSQL 16 | 关系型 + JSONB 支持 |
| **缓存** | Redis 7 | 会话、状态、限速 |
| **消息队列** | RabbitMQ | 工作流异步执行 |
| **ORM** | GORM | Go 生态最成熟的 ORM |
| **API 文档** | Swagger / swaggo | 自动生成 API 文档 |
| **CI/CD** | GitHub Actions | 自动化构建与部署 |

## 6. M2.5: Agent 对话与系统提示词（补充开发, M5 启动前）

### 6.1 目标

让 Agent 成为可用的"对话型"实体：可配置系统提示词, 用户输入用户提示词后获得 Agent 应答文本与执行结果, 每次执行有明确起止、全程可追溯。原"实例常驻 + 模拟流量"语义收敛为：实例启动 = 上线 (可接受对话/调用), 自主流量模拟改为显式开关 (默认关闭)。

| 序号 | 任务 | 预计工时 | 负责人 | 前置条件 |
|------|------|----------|--------|----------|

| M2.5.2 | 系统提示词: agents/agent_versions 增加 system_prompt 字段 (AutoMigrate), 创建/更新 API 携带, 参与版本历史与回滚 | 0.5d | 后端 | M2 |

| M2.5.5 | 对话会话持久化: agent_chat_sessions / agent_chat_messages 表 + 会话列表/消息历史 API (最近 N 轮作为多轮上下文) | 1d | 后端 | M2.5.4 |

## 12. 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 工作流 DAG 引擎复杂度超预期 | 高 | 中 | 先实现线性 DAG，分支/循环延后到 Phase 2 |
| MCP 服务器协议差异 | 中 | 中 | 使用适配器模式，优先支持 stdio 协议 |
| 前端编辑器开发难度 | 中 | 高 | 选用 x6/graph-editor 成熟库，快速搭建 |
| 高并发下消息队列积压 | 低 | 高 | 引入消费者限流 + 死信队列 |
| 团队技术栈学习曲线 | 中 | 中 | 预留 3 天 Go 语言集中培训 |
| 审核请求积压 (审核人不及时处理) | 中 | 中 | 默认超时拒绝 + 待审核数量徽标 + P2 通知 |
