## 1. 背景与目标

M11 P0（W1–W3）已于 2026-09-13 全量交付: 3 表 + pgvector 两阶段检索（HNSW 召回 + rerank, 四级降级）+ 一键总结入库 + 平台设置。总结文档 §6 列出 5 项剩余事项, 本计划将其转化为两个可验收阶段:

| # | 事项 | 优先级 | 现有基础 | 估算 |
|---|------|--------|----------|------|
| 1 | 多级分类（树形）+ 绑定父级含子级语义 | P1 | `kb_categories.parent_id` 预留（恒 NULL） | 9 人日 |
| 2 | 分类级只读绑定（跨团队共享只读消费） | P1 | `agent_kb_bindings.read_only` 预留（恒 false） | 6.5 人日 |
| 3 | 向量回填异步任务化（后台任务 + 进度查询） | P2 前置（衔接项） | 手动回填当前同步于请求内执行 | 5.5 人日 |
| 4 | 条目分块 + 块级向量（长文命中精度） | P2 | 整条单向量（embedding 文本截断 8000 字符） | 10 人日 |
| 5 | README M10 模块状态补记 + 权限点数修正 | 文档 | 纯文档缺口（历史遗留, 与 M11 无关） | 0.5 人日 |

合计约 31.5 人日。分两轨: **轨道 A = P1（事项 1 + 2 + 5）**, **轨道 B = P2（事项 3 + 4）**; 事项 3 排在事项 4 之前（块级回填复用任务框架, 见 §2.4 / §2.3）。

**目标（逐项一句话）:**

1. 两级分类树（顶级 + 子级）: 管理端 UI 树形化; Agent 绑定顶级分类时其全部子分类自动进入读/写作用域;
2. Agent 分类绑定增加只读降权选项: 只读分类可被检索, 禁止写入（总结入库）;
3. 向量回填由同步请求转后台任务: 启动 / 进度查询 / 取消, 状态持久化, 服务重启可恢复;
4. 长条目按 Markdown 结构分块, 检索 / 向量化 / 注入摘录均按块进行; 短条目行为与现状一致（1 块 = 整条）;
5. README 补齐 M10 记忆模块（总览 / 状态 / 操作说明）并修正权限点数。

## 2. 详细需求

### 2.1 事项 1: 多级分类（P1, A12–A16）

**功能需求**

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 两级层级 | `parent_id` 启用: 顶级分类（parent_id=NULL）+ 子级分类; 子级不能再有子级（PRD §3.1「parent_id 两级层级」） | P1 |
| 名称唯一性 | 由 P0「平台内唯一」放宽为**同一父级下同级唯一**（大小写不敏感）; UI 展示完整路径「父/子」消除歧义。存量数据本已全局唯一, 放宽对存量安全（无需数据修复） | P1 |
| 新建分类 | `parent_id` 可选, 必须指向顶级分类否则 400; 同级重名 → 400 | P1 |
| 重命名 / 改描述 | 现有规则不变（名称重新校验唯一性, 审计） | P1 |
| 移动父级 | `PUT /kb/categories/:id` 支持 `parent_id` 变更; **已有子级的分类不可降为子级**（400, 会突破两级约束）; 移动重新校验同级唯一 + 审计 | P1 |
| 删除保护 | 现有规则: 有条目 → 409; 新增: **有子级分类 → 409**（提示先删除或迁移子级） | P1 |
| 绑定语义（核心） | **绑定顶级分类自动含其全部子级**: 读 = 每轮注入 + `search_knowledge` + Agent 试算均命中父 + 子条目; 写 = 一键总结入库目标分类可为绑定的顶级分类或其任一子级。绑定表仍只存绑定分类行（绑父不建子绑定行）, 扩展在运行时完成 | P1 |
| 试算作用域 | Agent 试算（`GET /agents/:id/kb/search`）继承绑定扩展; 平台试算（`GET /kb/search`）**不自动扩展**（用调用方显式分类集; 平台视角 = 显式预览, Agent 视角 = 绑定语义） | P1 |
| 管理端 UI | KbListPage 左侧平铺列表 → 两级树（带条目数; 点顶级分类筛选父 + 子条目）; 新建/编辑弹窗增加父级选择器（仅顶级分类可选） | P1 |
| Agent 表单 | 分类多选改两级 `TreeSelect`; 用户同时勾选顶级与其子级时**仅提交顶级**（前端去重; 后端幂等不受影响） | P1 |
| Agent 详情 | KB 页签分类展示「父/子」路径 | P1 |

**数据变更**: 无新列; `parent_id` 索引 `idx_kb_category_parent`; 存量数据零 DDL（全 NULL）。唯一性校验维持应用层（与 P0 一致, 不加 DB 唯一约束; 并发创建竞态 P0 已存在, 本周期不处理）。

**验收标准**

- A12: 两级分类树创建; 同级重名 400; 不同父下子级可同名
- A13: 绑定顶级 → Agent 注入 / `search_knowledge` / 试算命中父 + 子条目; 仅绑子级 → 只命中该子级
- A14: 一键总结可写入绑定顶级的子级; 写入未绑定分类仍 403
- A15: 有子级分类删除 → 409; 子级清空后可删; 有子级分类移动父级 → 400
- A16: 新建 / 重命名 / 移动 / 删除均审计（`kb.category_*`, detail 含 parent_id / 新旧值）

### 2.3 事项 3: 向量回填异步任务化（P2 前置衔接项, A21–A24）

**动机**: 当前 `POST /kb/documents/backfill-embeddings` 同步于请求内执行, 规模大时长占位; 事项 4 引入后回填对象由条目变为块（2–4 倍）, 长任务不可避免。

**功能需求**

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 任务表 | 新 `kb_backfill_tasks`: id / status（`pending`/`running`/`succeeded`/`failed`/`cancelled`）/ total / done / failed / last_error / created_by / created_at / started_at / finished_at; 状态持久化 DB, 进度可查 | P1 |
| 单飞 | 平台同时仅一个任务可运行; 重复启动 → 409（返回运行中任务 ID） | P1 |
| 执行 | 进程内单 worker goroutine（与平台现无队列基建风格一致, 零新依赖）; 批次 32（复用 `EmbedBatch`）, 批边界更新进度 | P1 |
| 取消 | `POST .../cancel`: 仅 pending/running 可取消; running 在批边界协作取消（当前批完成后停止） | P1 |
| 重启恢复 | 进程启动时残留 `pending`/`running` 任务 → `failed`（last_error="service restart"）, 之后可新启动 | P1 |
| 旧端点 | `POST /kb/documents/backfill-embeddings` → **410 Gone**（消息指明新端点）; 前端 / E2E / 文档同周切换 | P1 |
| 前端 | 平台设置「向量回填」→ 启动任务 + 进度条（2s 轮询）+ 最近 5 条任务（状态 / 进度 / 错误 / 取消） | P1 |
| 并发写 | 写路径 `VectorizeAsync`（fire-and-forget）与任务可能并发写同一向量: 向量写幂等（仅 `embedding IS NULL` 时写入, 内容确定, 后写胜）, 无竞争 | P1 |

**验收标准**

- A21: 启动任务 → 状态机 `pending→running→succeeded`, 进度（done/total）单调且与 DB 一致
- A22: 重复启动 409; 取消 → `cancelled`（批边界停止, 不断当前批）
- A23: 任务运行中重启服务 → 任务标 `failed`（restart）, 可再启动
- A24: 前端进度条 / 任务列表展示正确（UI smoke）; 旧端点 410 消息指明新端点

### 2.4 事项 4: 条目分块 + 块级向量（P2, A25–A30）

**问题**: 当前整条单向量（embedding 文本 = 标题 + 正文截断 8000 字符）。长条目的关键段落信号被整条向量稀释, 且头部截断导致后半段信息丢失, 长文知识（SOP / 排障手册）命中精度差。

**设计决策**

| 方面 | 决策 | 说明 |
|------|------|------|
| 分块算法 | Markdown 结构感知: 标题为一级边界, 段落为基础单元; 目标块大小 `KB_CHUNK_SIZE`=500 字符, 相邻重叠 `KB_CHUNK_OVERLAP`=50 字符; 纯函数实现可单测 | 取代现有 `kbEmbedText` 截断策略 |
| 分块阈值 | 正文 ≤ `KB_CHUNK_THRESHOLD`=1000 字符 → 整条 1 块（行为与现状一致）; 超过才分块 | 短条目不受影响, 回归面小 |
| 存储 | 新表 `kb_chunks`: id / doc_id / chunk_index（unique (doc_id, chunk_index)）/ content / embedding `vector(1024)` NULL / updated_at; HNSW 部分索引 `WHERE embedding IS NOT NULL` | `kb_documents` 主表零结构影响 |
| 写路径 | 条目创建/更新 → **同事务重建块**（删旧 + 插新, 向量 NULL）→ `VectorizeAsync` 由整条改按块异步向量化; 仅改标题 / 来源不触发重建 | 条目落库主流程不阻塞（块同事务, 向量化异步） |
| 检索路径 | 向量召回改走 `kb_chunks` HNSW（候选数 = `KB_RECALL_SIZE × KB_CHUNK_RECALL_MULT`(=2), 块级）→ **按条目聚合**（每条目取 best chunk 分）→ top `KB_RECALL_SIZE` 条目 → rerank（文本 = 标题 + best chunk）→ top-K; **关键词路径不动**（整条打分, 减小变更面） | 四级降级阶梯保留 |
| 注入摘录 | 长条目输出**最佳命中块**（替代固定头部摘录）; `KBSearchHit` 增 `matched_chunk` 摘录字段; `KB_CHAR_BUDGET`=4000 总预算逻辑不变 | 访问统计仍按条目（`access_count`） |
| 存量数据 | 上线时迁移阶段为全部现存 active 条目**同步生成块**（纯 CPU 切分, 不含向量, 万级条目秒级完成）; 向量化由回填任务（事项 3）完成 | 不新增迁移端点, 在 `database.Init` 阶段执行（仅 `KB_CHUNK_ENABLED=true` 时） |
| 回退开关 | `KB_CHUNK_ENABLED`（默认 true）: false = 整条向量路径全量回退（`kb_documents.embedding` 数据保留可用） | 大切换保险 |
| 列废弃 | `kb_documents.embedding` 本版本起停写, 列保留（数据保留 + 回退）, 文档标注 deprecated | |

**API / 前端**

- `GET /kb/documents/:id/chunks`（`kb:read`）: 块列表（序号 / 摘录 / 向量化状态）, 管理预览与调试
- 条目详情响应 + `chunk_count`
- 前端: 条目详情抽屉「分块」页签（列表 + 向量化状态徽标）; 试算结果卡片展示命中块摘录（长条目）; 平台设置配置 embedding 模型且存在未向量化块时提示回填

**新增环境变量**（5 项, 均有默认值, docker-compose 注入）: `KB_CHUNK_SIZE`=500 / `KB_CHUNK_OVERLAP`=50 / `KB_CHUNK_THRESHOLD`=1000 / `KB_CHUNK_RECALL_MULT`=2 / `KB_CHUNK_ENABLED`=true

**验收标准**（mock `/v1/embeddings` 为确定性 FNV-bigram 伪向量, 查询文本 == 块文本 → 余弦 1.0 top-1 命中, mock E2E 可行, 与 M11 向量路径 E2E 同思路）

- A25: 分块器单测全绿（标题边界 / 段落合并 / 重叠 / 字数上限 / 空正文 / 阈值短条目 1 块）
- A26: 长条目中段有关键段 → 向量召回命中该条目且摘录 = 该块（非头部摘录）
- A27: 条目编辑 → 块重建（旧块删除, 新块写入）; 重建后未向量化期间不命中向量路径, 回填后命中
- A28: 块级回填: 启动任务 → 全部未向量化块完成; 完成后向量路径可用
- A29: 存量迁移: 启动后 active 条目具备块; 回填完成后检索链路可用
- A30: 短条目（≤ 阈值）行为与现状一致（1 块, 整条向量）; `KB_CHUNK_ENABLED=false` 回退路径可用（回退演练）

## 4. 数据模型变更

| 表 | 变更 | 说明 |
|----|------|------|
| `kb_categories` | 无新列; `parent_id` 启用 + `idx_kb_category_parent` 索引 | 存量全 NULL, 零 DDL |
| `agent_kb_bindings` | 无新列; `read_only` 启用（默认 false） | 存量全 false（= 读写）, 语义不变 |
| `kb_chunks` | **新表** | id / doc_id / chunk_index / content / embedding `vector(1024)` NULL / updated_at; unique (doc_id, chunk_index); HNSW 部分索引 |
| `kb_backfill_tasks` | **新表** | id / status / total / done / failed / last_error / created_by / created_at / started_at / finished_at |
| `kb_documents` | 无结构变更; `embedding` 列 deprecated（停写, 保留） | 回退开关依赖该列数据 |

迁移: GORM AutoMigrate（2 新表 + 2 索引）+ HNSW 幂等建索引; 存量分块迁移为数据操作（纯 CPU 切分, 分批执行于 `database.Init` 阶段, 幂等可重跑）。

## 9. 风险与应对

| 风险 | 等级 | 应对 |
|------|------|------|
| 分块路径大切换, 检索链回归面大 | 高 | `KB_CHUNK_ENABLED` 回退开关（A30 回退演练）+ 短条目路径不变 + 四级降级保留 + 87 项回归全绿作为交付门禁 |
| 双轨并行改 `kb_retriever.go` / API, 合并冲突 | 中 | 合并顺序约束（§8）: A 作用域扩展先行, B rebase; E2E 分文件; W2 D10 B 轨回归跑一次作为冲突检测点 |
| 名称唯一性放宽（全局 → 同父）用户预期不一致 | 低 | UI 展示完整路径; A12 覆盖边界; 存量数据全局唯一, 放宽不违反任何存量约束 |
| 绑定作用域父子扩展影响存量 Agent | 低 | 存量无父子（parent_id 全 NULL）, 扩展 no-op; 启用树后仅影响新建的父子分类 |
| 只读绑定 API 变更影响存量客户端 | 低 | 纯新增可选字段; 不传 = 全读写（A20 含旧 payload 兼容用例） |
| 回填任务与 `VectorizeAsync` 并发写向量 | 低 | 向量写幂等（仅 NULL 时写, 内容确定, 后写胜） |
| 分块上线时存量条目重新向量化 token 成本 | 中 | 回填任务可取消 + 批次 32 + 批边界限速; 迁移阶段仅 CPU 切分不耗 token |
| 块表规模增长（万级条目 → 2–4 万块） | 低 | HNSW 百万级容量; 块召回候选数 ×2 上限（40）; W4 EXPLAIN 抽测点 |
| 旧回填端点 410 影响外部调用方 | 低 | M11 回填端点仅平台设置页使用（非 external API）; 410 返回明确新端点指引; api.md 同步 |
