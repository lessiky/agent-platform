### 1.3 回填任务框架（事项 3）

- 状态机 `pending → running → succeeded/failed/cancelled`, 进度批边界落库, 查询契约 `0 <= done <= total`
- **单飞**: 平台同时仅一个任务; 重复启动 → 409（`kb_task_active`, 消息/body 含运行中任务 ID）; 已结束任务再取消 → 400
- **取消**: 批边界协作停止（当前批完成后停止, 不断批）, 终态 `cancelled`
- **重启恢复**: 进程启动时残留任务 → `failed`（`last_error="service restart"`）, 之后可新启动（`MarkOrphansFailed`）
- **旧端点**: `POST /kb/documents/backfill-embeddings` → **410 Gone**（消息指明 `POST /kb/backfill-tasks`）; 前端/E2E/文档同周切换
- 并发写安全: 写路径 `VectorizeAsync` 与任务并发写同一向量时, 仅 `embedding IS NULL` 时写入（幂等, 后写胜）

### 1.4 分块 + 块级向量（事项 4）

- **分块算法**（纯函数, 单测覆盖）: 标题为一级边界, 段落为基础单元; 目标 500 字符, 相邻重叠 50; 阈值内短条目 = 1 块（整条, 行为与现状一致）
- **写路径**: 创建/编辑/删除同事务块重建（`CreateWithChunks` / `UpdateWithChunks` / `DeleteWithChunks`）, 新块异步向量化; 未向量化期间不命中向量路径（不降级关键词）
- **检索路径**: 块级 HNSW 召回（候选 = 20 × 2）→ 按条目聚合 → rerank（用命中块文本）→ 注入摘录 = 命中块; 视图返回 `matched_chunk`
- **回退开关**: `KB_CHUNK_ENABLED=false` → 全量回退整条向量路径（doc 级回填 / doc 级召回 / 写路径不产块）, 四级降级保留
- **回填任务对象**: chunk 模式下任务处理未向量化**块**（`unit=chunk`）; 回退模式处理整条（`unit=document`）

### 2.1 回退演练（A30b）: 第二实例 :8091 同库

`KB_CHUNK_ENABLED=false` 容器（`kb-nochunk-backend`）与主实例共享同一数据库: `backfill-status unit=document`; 块模式未写整条向量（embedding NULL）; doc 级回填任务 succeeded → 整条向量回填 → doc 级向量召回可用（无 `matched_chunk`）; 回退模式写路径 201 且不生成块。

### 2.2 A30(b) 拆分与根因（W3 联调发现）

A30(b) 原与 A25–A30(a) 同脚本串行。W3 联调期该段连续 3 次失败, 现象为 Docker Desktop daemon 运行中「无声死亡」（无错误日志/崩溃转储, 前端 30ms 内感知 SSE 断开）。W3 D11 定位根因:

1. **端口冲突**: 回退实例原用宿主端口 8081, 与前端容器发布端口（`FRONTEND_PORT:-8081`）冲突 — `docker run` 报 `port is already allocated`, 且失败后残留 Created 状态容器继续占用 DD 端口资源;
2. **daemon 死亡的触发源**: 旧脚本 `Stop-PortOwner 8081` 直接 Kill 占用端口的进程 — 该进程是 Docker Desktop 自身的端口代理（`com.docker.backend` / `wslrelay`）, 杀之即破坏 daemon 连接, 与「无声死亡」时间线吻合。

**处置（已落地）**:

- A30(b) 拆为独立脚本 `tests/kb-chunk-fallback-e2e.ps1`（自管 mock/夹具/清理, 幂等; 主脚本保留 A25–A30(a), 两脚本合起来完整覆盖 A30）;
- 回退实例改端口 **8091**（避开前端 8081）, 不再 Kill 任何宿主进程;
- 脚本加固: `Wait-Docker` 轮询 + 过半自动拉起 Docker Desktop; 失败残留容器（Created）在 finally 无条件清理;
- 端口冲突消除后 daemon 全程稳定（本轮 4 个脚本 + 3 次容器重启零死亡）。

## 3. 已知限制

- 回填任务为进程内单 worker（与平台无队列基建风格一致, 零新依赖）, 无跨实例 HA; 重启后任务标记 failed 而非自动续跑（按计划 §2.3）
- 块级召回候选数固定为 2×RECALL_SIZE; 超长条目块数约为条目的 2–4 倍, 回填耗时相应增加
- `KB_CHUNK_ENABLED` 切换需重建块/向量（切换后建议跑一次回填任务）; 运行期不热切
- 回退演练独立运行: 需要 docker daemon 可用（脚本内置自动拉起）, 运行期间 :8091 端口需空闲
