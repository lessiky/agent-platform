## 1. 产品概述

### 1.1 背景

随着 AI Agent 技术在企业内部的广泛使用，团队需要统一的基础设施来管理 Agent 的全生命周期、MCP（Model Context Protocol）服务器资源、LLM 模型资源以及自动化工作流。当前分散的运维方式导致资源利用率低、权限边界模糊、故障排查困难。

### 1.2 目标

构建一个统一的 Agent 管理平台，实现以下核心能力：

| 能力域 | 描述 |
|--------|------|
| **Agent 管理** | Agent 的创建、部署、运行状态监控、版本管理、权限控制 |
| **MCP 管理** | MCP 服务器的注册、配置、连接健康检查、密钥/凭证管理 |
| **技能管理** | 技能包的导入/删除/升级、Agent 关联、运行时提示词注入与使用追溯 |
| **模型管理** | LLM 模型模板管理、参数配置、配额控制、路由选择、连接测试 |
| **工作流管理** | 可视化编排 DAG 工作流、调度管理、执行日志追踪、失败重试 |

### 1.3 用户角色

| 角色 | 权限 |
|------|------|
| **管理员** | 全局配置、用户/团队管理、资源分配、审计日志 |
| **开发者** | Agent/MCP/工作流的创建、编辑、部署；技能导入/删除与 Agent 关联 |
| **运维** | 运行监控、故障排查、健康检查、告警配置 |
| **观察者** | 只读查看 Agent、MCP、技能、工作流的运行状态与日志 |

#### 2.1.4 Agent 对话 (Chat)

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 系统提示词 | Agent 注册/编辑时可配置系统提示词 (system prompt)，定义 Agent 角色与行为规范，每次模型调用注入 | P0 |
| 对话交互 | 用户输入用户提示词 -> 平台组装 [系统提示词 + 会话历史 + 用户提示词] 调用模型 -> 返回 Agent 应答文本与执行元数据 (使用模型/tokens/延迟/工具调用细节) | P0 |
| 多轮对话 | 对话会话持久化，可浏览历史会话；最近 N 轮上下文送入模型 | P0 |
| 对话内工具调用 | 模型可调用 Agent 绑定的 MCP 工具 (受可用工具集限制)；需审核工具须人工审核通过后执行 (见 2.2.4) | P1 |
| 执行可追溯 | 每次对话执行生成 execution_id，运行日志记录执行开始与结束 (含模型/token/延迟/工具调用/待审核状态)，执行有明确起止 | P0 |
| 技能注入 | Agent 可关联技能包；每次模型调用按 agent 使用模式注入关联技能 (渐进式披露：目录 + `load_skill` 按需加载 / 全量注入)，技能加载明细计入执行元数据 (见 2.5.5) | P0 |

对话执行链: 用户提示词 -> 模型调用 (按 M4 路由选择模型/故障转移/消费配额; 技能注入见 2.5.5) / (模型请求工具调用时) MCP 工具执行 (走 2.2.4 审核门禁, 待审核工具不执行并在结果中标注) / (模型请求技能加载时) 平台返回技能指令正文 (`load_skill` 内置工具, 无需审核) -> 返回应答文本 + 执行元数据 (含技能加载明细)。

#### 2.2.4 工具调用人工审核 (Human-in-the-Loop)

部分 MCP 工具具有难以回滚的副作用或高风险操作（如数据写入、工单创建、资金操作），其调用必须经人工审核通过后才可执行。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 工具级审核配置 | 在 MCP 工具列表上配置 `requires_approval` 开关，支持逐工具设置与批量开启；工具重新发现时保留已配置标记 | P0 |
| 审核请求 | 调用需审核的工具时不立即执行，生成审核请求（含 Agent、工具、参数、调用来源、时间）；同工具并发调用各自独立成单，一次调用一次审核 | P0 |
| 审核操作 | 审核人通过 / 驳回（附意见）；通过后执行工具并回填结果，驳回 / 超时则终止本次调用 | P0 |
| 审核超时 | 审核请求带可配置超时（默认 30 分钟），到期未处理标记为 expired 并按超时策略执行（默认拒绝，可配置自动通过） | P0 |
| 审核权限 | 仅 `mcp:approve` 权限用户可审批；审核操作（人/时间/结论/意见）全部记入审计日志 | P0 |
| 审核中心 | 待审核列表（实时轮询）、审核详情（参数展示 / 调用来源 / 已等待时长）、通过 / 驳回操作、审核历史与筛选 | P0 |
| 同步调用行为 | API Key 外部调用 (/invoke) 遇到需审核工具时返回 202 + 审核请求 ID，不阻塞等待；执行结果在审核详情中查看 | P0 |
| 工作流联动 | 工作流 MCP 工具节点遇到需审核工具时节点进入 `waiting_approval`、执行挂起，审核通过后恢复，驳回 / 超时按节点容错策略失败 (随 M5 交付) | P1 |
| 审核通知 | 新审核 / 超时提醒通知（邮件 / IM webhook） | P2 |

业务规则：
- 审核请求仅允许 `mcp:approve` 权限用户审批，状态机保护（同一请求不可重复审批）。
- 审核通过后执行工具，执行失败仅将失败原因记入审核请求的 result，不回滚审核状态。
- 审核配置与 Agent 可用工具配置 (`config.tools`) 叠加生效：需审核但未通过的调用不计为成功调用。

### 2.5 技能管理模块

技能包是可复用的能力包：由一个 `SKILL.md` 描述技能名称、描述与完整指令正文，附带可选资源文件（脚本 / 模板 / 参考资料等）。技能包绑定 Agent 后，按 agent 配置的使用模式将技能内容注入模型上下文，扩展 Agent 的领域能力，无需改动 MCP 与模型配置。

#### 2.5.1 技能包规范

| 项 | 规则 |
|------|------|
| 包格式 | Zip 压缩包 (UTF-8 文件名)；接受 "根目录直接含 SKILL.md" 与 "单一顶层目录内含 SKILL.md" 两种结构 |
| SKILL.md frontmatter (YAML) | `name` 必填 (匹配 `^[a-z0-9]([a-z0-9-]{0,62}[a-z0-9])?$`)、`version` 可选 (semver, 默认 1.0.0)、`description` 必填 (≤512 字符)、`author` 可选、`tags` 可选 (≤10 个)、`required_tools` 可选 (技能依赖的 MCP 工具名数组, 与 Agent 配置 `tools` 同格式) |
| 指令正文 | frontmatter 之后的 Markdown 正文，非空，≤200KB |
| 资源文件 | 相对路径；禁止绝对路径、`..` 与空字节；文件类型白名单 (md/txt/rst/json/yaml/yml/toml/csv/tsv/html/css/py/js/ts/sh/bat/ps1/sql/xml/png/jpg/jpeg/gif/svg/pdf)，可配置 |
| 大小限制 | 包总大小 ≤10MB、文件数 ≤500、单文件 ≤2MB，均为平台级可配置项 |
| 名称唯一 | 技能名全局唯一；同名导入默认拒绝 (409 冲突)，可强制重导入执行 "升级" (见 2.5.2) |

**安全边界（硬约束）**：平台对技能包仅做存储与只读注入，不执行包内任何代码（含脚本）。包内脚本仅供模型参考或人工执行；Agent 需要执行带副作用的操作时，必须走既有 MCP 工具（含 2.2.4 人工审核）链路。

#### 2.5.2 技能包导入

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 导入入口 | UI：技能列表页拖拽 / 选择文件上传；API：`POST /api/v1/skills/import` multipart 上传 | P0 |
| 导入校验 | 解压 → 路径安全校验 (防 zip-slip) → 结构校验 (SKILL.md / frontmatter / 大小 / 文件数 / 文件类型) → 名称冲突检查；任一失败返回具体错误码与原因，不写入任何数据 | P0 |
| 冲突处理 | 同名已存在：默认拒绝；`force=true` 时以升级覆盖既有技能 (版本号 +1、文件替换、Agent 关联保留、下次执行即生效) | P0 |
| 并发安全 | 同名并发导入依赖数据库名称唯一约束，失败方返回 409 | P0 |
| 审计 | 导入 / 升级操作 (操作人 / 包名 / 版本 / 结果) 记入审计日志 | P0 |
| 批量导入 | 多文件批量上传，逐个校验导入并返回逐项结果 | P2 |
#### 2.5.3 技能列表、详情与删除

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 技能列表 | 按名称 / 描述搜索，按标签 / 状态筛选；展示版本、大小、关联 Agent 数、"使用中" 标记 | P0 |
| 技能详情 | 元数据、SKILL.md 渲染预览、文件树 (单文件预览 / 下载)、关联 Agent 列表 (含操作人 / 时间)、使用统计 | P0 |
| 状态控制 | 技能状态 active / disabled；禁用后运行时不注入，Agent 关联保留，重新启用即恢复 | P0 |
| 元数据更新 | 修改 tags、description、author (不改变指令正文)；指令正文变更仅可通过升级导入 | P1 |
| 技能删除 | 已被 Agent 关联时默认拦截并返回关联列表；`force=true` 允许级联解绑 (清理绑定表)；删除后历史执行中的技能引用保留 名称 + 版本 快照 | P0 |
| 技能版本管理 | 同名升级保留历史版本快照，支持版本对比与回滚 | P1 |

#### 2.5.4 Agent 关联

| 双向可见 | Agent 侧查看关联技能 (含元数据)；技能详情页查看关联 Agent | P0 |
| 依赖校验 | 技能声明 `required_tools` 时，关联时校验工具在 Agent 可用工具集内 (MCP 绑定 ∩ `config.tools`)，不满足则拒绝关联并列出缺失工具；运行期若后续配置变更导致关联失效，`load_skill` 返回警告并将执行元数据标记为 `partial` | P0 |
| 注入预算 | 全量注入模式下，校验关联技能指令正文总长度不超过平台配置 (默认 128KB, 可配置)，超出则拒绝关联 | P0 |
| 关联权限 | 需 `skill:write`；Agent 侧操作另需 `agent:write` | P0 |
| 单技能开关 | 按 Agent 对单个技能启用 / 停用、版本锁定 (绑定特定版本, 不受升级影响) | P2 |

#### 2.5.5 运行时使用

技能注入支持两种使用模式，Agent 级配置 `skills_usage_mode` (存于 `config` JSONB)，默认 A：

- **A. 渐进式披露 (`metadata_injection`，默认)**：每次模型调用时在系统提示词追加 "技能目录" (每个技能名称 + 描述 + 加载说明)；平台提供内置工具 `load_skill(skill_name)`，模型需要时主动加载完整指令正文，正文以工具结果返回，同一执行内重复加载返回简短确认。Token 消耗低，适合技能数量多的场景。
- **B. 全量注入 (`full_injection`)**：每次模型调用时将所有关联技能正文直接注入系统提示词，无需按需加载。适合技能少且短的场景。

| 功能 | 描述 | 优先级 |
|------|------|--------|
| 对话链路 | 对话执行链默认生效：系统提示词组装后按模式追加技能段 (目录或正文)；`load_skill` 为平台内置工具，只读无副作用，不走 2.2.4 人工审核；Agent 未关联技能时不注入、不注册内置工具 | P0 |
| 执行追溯 | 每次执行 `execution_meta.skill_calls` 记录技能加载明细 (技能名 / 版本 / 模式 / 字符数 / 延迟 / 状态)，技能内容计入执行 prompt token 统计 | P0 |
| 外部 API 调用 | API Key 外部调用 (/invoke) 与对话同一执行链，默认生效 | P0 |
| 工作流联动 | 工作流 Agent 节点继承 Agent 的技能关联与注入模式 | P1 |
| 使用统计 | 技能列表 / 详情页展示关联数、近 30 天加载次数、最近使用时间 | P0 |
| 使用趋势 | 按 Agent 维度查看技能使用趋势 | P2 |

#### 2.5.6 权限与审计

| 功能 | 描述 | 优先级 |
|------|------|--------|
| RBAC | `skill:read` (列表 / 详情 / 预览 / 文件下载 / 统计)、`skill:write` (导入 / 升级 / 元数据 / 删除 / 关联管理) | P0 |
| 审计日志 | 导入 / 升级 / 删除 / 绑定 / 解绑 / 状态变更均记录 (操作人 / 对象 / 前后摘要 / 结果) | P0 |
| 全局配置 | 包大小 / 文件数 / 单文件大小 / 文件类型白名单 / 全量注入预算，平台级可配置 (管理员) | P1 |

## 3. 非功能需求

### 3.1 性能

| 指标 | 目标值 |
|------|--------|
| 平台 API 响应 | P95 < 200ms |
| 工作流编排加载 | < 2s |
| Agent 状态更新延迟 | < 5s |
| 日志查询 | 支持亿级日志，P95 < 3s |

### 3.2 可靠性

- 平台可用性 SLA ≥ 99.9%
- 支持多副本部署，单点故障不影响整体服务
- 数据持久化，支持每日自动备份

### 3.3 安全性

- 全链路 HTTPS/TLS 加密传输
- 所有敏感凭证加密存储
- API Key 最小权限原则
- 审计日志不可篡改 (WORM 存储)
- 支持 SSO / LDAP / OAuth2 集成
- 高风险 MCP 工具调用支持人工审核 (Human-in-the-Loop)，审核操作纳入审计日志 (见 2.2.4)
- 技能包导入安全：文件类型白名单、大小 / 文件数限制、路径安全校验 (防 zip-slip)；平台不执行包内任何代码 (见 2.5.1)

### 3.4 可扩展性

- 微服务架构，各模块可独立扩缩容
- 支持水平扩展 Agent 运行时
- 插件化 MCP 服务器适配器
- 开放 RESTful API，支持第三方集成

### 3.5 可观测性

- Prometheus + Grafana 指标监控
- 结构化日志 (JSON 格式)
- OpenTelemetry 分布式追踪
- 集中式日志收集 (ELK / Loki)

## 9. 风险与依赖

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Agent 运行时兼容性问题 | 多框架 Agent 共存困难 | 定义标准化 Agent 契约接口 |
| 工作流状态管理 | 中断恢复复杂 | 采用事件溯源模式持久化状态 |
| 高并发 Agent 调用 | 性能瓶颈 | 引入消息队列削峰、连接池 |
| MCP 服务器多样性 | 不同实现协议差异 | 适配器模式封装传输层 |
| 安全合规 | 凭证泄露、越权访问 | 最小权限原则 + 全链路加密 + 审计 |
| 恶意 / 超大技能包 | 提示词注入、存储压力、安全风险 | 导入时校验 (白名单 / 大小 / 路径安全) + 平台不执行包内代码 + 审计；技能内容按数据处理而非指令 |
| 技能内容占用过多 Token | 模型上下文被挤占、成本上升 | 默认渐进式披露使用模式 + 全量注入预算校验 (见 2.5.5) |

## 10. 附录

### 10.1 术语表

| 术语 | 说明 |
|------|------|
| **Agent** | 基于大语言模型，可调用工具和记忆的自主推理实体 |
| **MCP** | Model Context Protocol，开放模型连接协议 |
| **Skill (技能包)** | 可复用能力包：SKILL.md (名称 / 描述 / 指令正文) + 可选资源文件，绑定 Agent 后按需注入模型上下文 (见 2.5) |
| **DAG** | 有向无环图，用于描述工作流的节点执行顺序 |
| **RBAC** | Role-Based Access Control，基于角色的访问控制 |
| **人工审核 (HITL)** | Human-in-the-Loop，特定操作须经人工确认后才可执行的机制 (见 2.2.4) |
| **Agent 对话 (Chat)** | 用户输入提示词、Agent 经模型调用返回应答的交互形式, 含对话内工具调用与多轮会话 (见 2.1.4) |
| **SLA** | Service Level Agreement，服务等级协议 |
